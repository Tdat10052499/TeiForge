## 1. Bối cảnh

Đánh giá mã nguồn v0.2.0 cho thấy bốn nhóm vấn đề cần xử lý trước khi phát hành rộng rãi dưới dạng công cụ mã nguồn mở:

## 2. Mục tiêu v0.3

1. **Phát hành được:** tên mới `teiforge`, lệnh `teiforge`, một nguồn phiên bản duy nhất.
2. **An toàn mặc định:** công cụ tệp chỉ hoạt động trong workspace, không ghi đè nếu không yêu cầu.
3. **Agent đúng nghĩa:** vòng lặp tool-calling khi có LLM; bộ định tuyến từ khóa (đã sửa) khi không có LLM.
4. **Nền cho giao diện sau này:** mọi lần chạy phát ra chuỗi sự kiện có cấu trúc.
5. **Chất lượng có kiểm chứng:** CI chạy ruff, mypy, pytest kèm ngưỡng coverage.

Ngoài phạm vi v0.3 (để dành cho v0.4): web UI, search provider có thể thay thế, async/streaming, docs site.

## 3. Thiết kế

### 3.1 Đổi tên

- Distribution và import: `agentforge` → `teiforge`. Lệnh CLI: `teiforge`; `python -m teiforge` cũng chạy được.
- Không giữ shim `import agentforge`, vì tên này thuộc một dự án khác trên PyPI và giữ lại sẽ gây xung đột.
- Phiên bản: `teiforge/_version.py` là nguồn duy nhất, được `pyproject.toml` đọc qua `dynamic = ["version"]`.

### 3.2 Tool có schema (`teiforge/tools.py`)

- `ToolResult(ok, output, error)` thay cho việc dò tiền tố chuỗi.
- `ToolError`: tool raise ngoại lệ này cho lỗi người dùng; `Tool.run` chuyển thành `ToolResult(ok=False)`.
- Decorator `@tool` sinh JSON Schema từ type hints và docstring.
- `Tool.run()` nhận `dict` (tham số có cấu trúc) hoặc `str` (tương thích ngược với tool kiểu cũ `str -> str`).
- `Tool.to_openai_schema()` và `Tool.to_anthropic_schema()`.

### 3.3 Workspace sandbox (`teiforge/workspace.py`)

- `Workspace(root)`: mọi đường dẫn được resolve trong `root`; đường dẫn thoát ra ngoài (`..`, đường dẫn tuyệt đối, symlink) bị từ chối.
- Mặc định `root` = biến môi trường `TEIFORGE_WORKSPACE`, nếu không có thì thư mục hiện tại.
- `write_file` mặc định **không ghi đè**; cần `overwrite=True`.
- Cú pháp cũ `write:path:content` hỗ trợ ổ đĩa Windows (`C:\...`, `C:/...`).

### 3.4 Nhà cung cấp LLM (`teiforge/llm.py`)

- Giao thức `LLMProvider.complete(messages, tools) -> LLMResponse(content, tool_calls)`.
- `OpenAIProvider` (có `base_url`, nên dùng được Ollama, LM Studio, OpenRouter và các API tương thích OpenAI).
- `AnthropicProvider` (gói phụ `teiforge[anthropic]`).
- `ScriptedProvider` trong `teiforge.testing` để viết test không cần mạng.
- `provider_from_env()` đọc `TEIFORGE_PROVIDER`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`.

### 3.5 Agent (`teiforge/agent.py`)

- `run(task) -> str` giữ nguyên chữ ký (tương thích ngược).
- `run_detailed(task, on_event=None) -> RunResult(output, ok, events, mode)`.
- Chế độ `llm`: vòng lặp tool-calling, tối đa `max_steps` bước, đưa lịch sử memory vào prompt.
- Chế độ `router`: khớp theo ranh giới từ (`\b`), nhận diện tiền tố tường minh (`read:`, `write:`, `search:`), tự trích đường dẫn tệp trong câu ("Read demo.txt if it exists" → đọc `demo.txt`).
- Chế độ `auto` (mặc định): dùng `llm` nếu có provider, ngược lại dùng `router`.

### 3.6 Sự kiện (`teiforge/events.py`)

Các loại sự kiện: `task_start`, `llm_response`, `tool_call`, `tool_result`, `final`, `error`. Đây là lớp dữ liệu mà CLI tương tác và web UI v0.4 sẽ dùng chung.

### 3.7 Memory và cấu hình

- `Memory.save(path)` / `Memory.load(path)` dạng JSON; `Memory.to_messages()` cho prompt.
- `AgentConfig` thêm `provider`, `base_url`, `max_steps`, `workspace`, `mode`; `AgentConfig.from_file()` đọc TOML hoặc JSON.

### 3.8 CLI

```
teiforge run "task" [--tools ...] [--no-llm] [--json] [--verbose] [--config FILE] [--workspace DIR]
teiforge search "query" [--out FILE] [--no-llm]
teiforge chat            # REPL: /help /tools /memory /save /clear /exit
teiforge tools           # liệt kê tool và schema
teiforge version
```

## 6. Việc tác giả cần làm thủ công

1. Đổi tên repo GitHub thành `teiforge` (Settings → Repository name). GitHub tự chuyển hướng URL cũ.
2. Xác nhận lại tên `teiforge` còn trống trên PyPI, và cấu hình Trusted Publisher cho workflow `release.yml`.
3. Bật GitHub Discussions nếu muốn giữ liên kết trong CONTRIBUTING.
4. Sau khi merge: tạo tag `v0.3.0` để kích hoạt phát hành.

## 8. Kết quả kiểm thử thủ công (`/tf-smoke-llm ollama`, 13/10/2026)

Môi trường: Windows, Ollama chạy trên máy, model `llama3.1:latest` (8B), `OpenAIProvider` với `TEIFORGE_BASE_URL=http://localhost:11434/v1`, temperature 0.7.

| # | Kịch bản | Kết quả | Bằng chứng chính |
|---|---|---|---|
| 1 | Câu hỏi không dùng tool | Đạt | `mode=llm`, `steps=1` |
| 2 | Đọc `notes.txt` rồi tóm tắt | Không ổn định (1/3) | Hai lần model in JSON gọi tool ra văn bản, không có `tool_calls` |
| 3 | Tool tự viết `multiply(a, b)` | Đạt | Model gửi đối số đúng kiểu số |
| 4 | Đọc `../outside.txt` | Đạt | `tool_result ok=false`, "outside the workspace"; nội dung tệp không bị lộ |
| 5 | CLI `teiforge run ... --json` | Đạt | Thoát với mã 0, JSON hợp lệ, có gọi `file_reader` |

Nhận định:

- Kịch bản 5 dùng cùng tool `file_reader` và gọi đúng, nên lỗi ở kịch bản 2 nhiều khả năng do model chứ không do TeiForge (giả thuyết, chưa chạy lại với temperature 0 hoặc model khác).
- Phát hiện kèm theo: system prompt mặc định luôn nhắc đến web search, kể cả khi agent không có tool này. Đã sửa trước khi phát hành (prompt chỉ liệt kê tool thật sự có), có test hồi quy.
- Chuyển sang v0.4: khi model trả lời gọi tool dưới dạng văn bản, TeiForge vẫn báo `ok=True`. Cần nhận diện trường hợp này rồi thực thi lời gọi, hoặc yêu cầu model gọi lại.
